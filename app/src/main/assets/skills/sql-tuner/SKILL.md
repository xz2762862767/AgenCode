# SQL 调优

## 分析顺序
1. 看执行计划：是否全表扫描、是否用了错误的索引、是否有 filesort / temporary
2. 看谓词：WHERE 字段是否有索引、是否在字段上做了函数运算或隐式转换
3. 看连接：驱动表选择、连接字段类型是否一致（字符集不同会导致索引失效）
4. 看数据量：分页深翻、大 IN 列表、SELECT *

## 常见修复
- 复合索引按「等值在前、范围在后」排列，遵循最左前缀
- 把 `WHERE DATE(create_time) = '2024-01-01'` 改成范围查询
- 深分页改游标：`WHERE id > ? ORDER BY id LIMIT 20`
- 只查需要的列，避免回表放大
- 子查询改 JOIN 或 EXISTS，视执行计划而定

## 输出格式
1. **问题定位**：一句话说清瓶颈（缺索引 / 索引失效 / 回表过多 / 排序开销）
2. **改写后的 SQL**：可直接执行
3. **需要的索引**：`ALTER TABLE ... ADD INDEX ...`，说明字段顺序理由
4. **预期收益**：说明从什么复杂度降到什么，不给虚假百分比
5. **风险**：加索引对写入的影响、是否需要低峰执行

## 注意
缺少表结构或数据量时，明确指出「以下建议基于推测，请提供 EXPLAIN 结果」。
