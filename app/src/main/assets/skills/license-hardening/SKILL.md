# 授权校验加固

方向明确：**保护自己的产品**，不是绕过别人的。

## 第一原则

**客户端不产生权益，只展示服务端给的结论。**

所有「是不是会员」的判断都在服务端完成。客户端拿到的一切都可以被改，
所以客户端永远只回答「服务端上次告诉我什么」，不回答「我应不应该放行」。

## 先查这六个常见错误

1. `isVip = true` 明文存在 SharedPreferences 或本地文件——改一行就破了
2. 只在启动时校验一次，通过后全程放行
3. 用 `System.currentTimeMillis()` 判断是否到期——改系统时间即可续期
4. 到期时间由客户端计算并存储
5. 校验集中在 Java 层一个方法里，反编译后改 `return true` 就结束
6. 服务端把全部权益数据下发，客户端自己过滤显示——抓包就能拿到

## 正确的架构

1. **登录**：服务端签发 access token（短期，如 15 分钟）+ refresh token
2. **权益接口**：`GET /entitlement` 返回 `{plan, expireAt, features[]}`，
   `expireAt` 用**服务端时间**，客户端只用于展示
3. **关键内容在服务端把关**：需要会员的接口，服务端查 token 对应权益，
   无权益直接返回 403 + 业务码。**绝不能只是前端把入口藏起来**
4. **短期 token**：退款、降级、封禁能在一个 token 周期内失效
5. **本地缓存**：可以存，但必须带 TTL，且服务端能一键作废

判断标准很简单：**即使用户把客户端改到完全信任自己，他也拿不到本该付费的内容。**

## 客户端加固（提高成本，不追求绝对）

- **签名校验**：`PackageManager.getPackageInfo(pkg, PackageManager.GET_SIGNING_CERTIFICATES)`，
  比对 `signingInfo.getApkContentsSigners()` 的 SHA-256。
  不要用已废弃的 `signatures` 字段——二次打包能伪造它
- **完整性**：Play Integrity API，`verdict` 必须送到服务端校验，客户端自判无意义
- **防调试**：检查 `ApplicationInfo.FLAG_DEBUGGABLE`、`Debug.isDebuggerConnected()`
- **防 hook**：检测常见注入痕迹（`/proc/self/maps` 里的 frida/xposed 特征、异常类加载器）。
  检测到后**静默降级**，不要弹「检测到破解」——那等于标出校验点位置
- **关键判断下沉到 native**：签名比对、权益解析放 JNI，Java 层只调结果
- **混淆**：开启 R8、字符串加密、敏感 API 走反射

## 输出时给这份清单

逐条打勾，指出用户当前缺哪几项：

- [ ] 权益判定全在服务端
- [ ] 无权益时接口返回 403，而非前端隐藏
- [ ] 本地只做缓存，带 TTL，可被服务端失效
- [ ] 到期判断用服务端时间
- [ ] 签名校验用 `GET_SIGNING_CERTIFICATES`
- [ ] 有完整性校验且 verdict 由服务端判定
- [ ] 关键逻辑在 native 层
- [ ] 已开 R8 混淆与字符串加密

## 注意

加固只提高破解成本，没有 100% 的方案。真正的护城河是服务端：
只要内容不下发给无权限的人，客户端怎么改都拿不到东西。

反过来，如果用户问的是「怎么绕过别人的会员校验」，说明方向相反，
不提供方法，可以转而聊上面这套防护怎么用在他自己的产品上。
