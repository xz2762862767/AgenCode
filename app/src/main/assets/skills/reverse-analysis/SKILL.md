# 逆向分析

定位：**理解程序怎么工作**。用于诊断自己的程序、分析样本、还原协议与格式、解题。
不覆盖绕过他人授权或付费校验——那是另一回事，不在本技能范围。

## 回答方式（先读这段，优先级最高）

- **用中文讲解为主**，讲清思路、判断依据、为什么这样做
- 工具命令只是背景知识，**不要当成回答模板**
- 需要给命令时，整段回答里最多出现两三条，且必须配一句说明它要验证什么
- **禁止**把回答写成命令清单，禁止整段贴代码或整屏命令
- 用户要的是「我该往哪看、为什么」，不是「给我一串命令去跑」

## 先分类，再选路径

不同目的入口完全不同，这是最容易走弯路的地方：

- **看懂 APK 结构、做体积或启动优化** → 解包看清单与资源，反编译看代码
- **排查自家 App 崩溃或异常行为** → 先抓日志异常栈，再回代码定位
- **分析可疑样本** → 隔离环境，静态特征加动态行为
- **理解第三方协议或文件格式** → 抓包加多样本结构比对
- **CTF / 算法还原** → 先黑盒跑通输入输出关系，再决定要不要读汇编

## Android 静态分析要点

- **先看 AndroidManifest，不要从头通读代码**：真实入口、导出组件、权限声明都在那里，能省掉大量时间
- 顺着入口 Activity → 网络层 → 数据模型这条线走
- 混淆过的代码先建调用链，不要硬读单行；类名失去意义，但调用关系仍是可靠线索
- 体积问题先按文件类型排序看谁占空间，通常是原生库、assets、图片三块

## 动态观察要点

- 查崩溃先抓异常栈，有了栈再回代码，不要先猜
- 想回答「这个值从哪来」，就在方法上观察入参出参，比读逻辑快
- 未知样本一律在隔离设备里跑，先断网看它想连哪

## 恶意样本分析（防御向）

- 静态先行：权限是否异常（短信、无障碍、设备管理）、有无动态加载 dex、有无硬编码服务器地址
- 动态跟进：隔离环境运行，观察网络请求、落地文件、自启方式
- 输出三样：**行为清单**（它做了什么）、**IOC**（域名、IP、文件路径、签名指纹）、**处置建议**
- 全程不在真机执行样本，不连生产网络

## 协议与文件格式

- 先判断链路是明文还是加密，自有流量可以用系统证书观察
- **结构比对法**：同类型多个样本逐字节比对，定位头部、长度字段、校验位，比单样本猜结构快得多
- 结论必须落成字段表：偏移、长度、含义、取值规律，而不是「大概是头部」
- 校验位先用简单样本验证和、异或、CRC 这类假设，不要一上来就上复杂猜测

## CTF 与算法还原

- 能黑盒推断就别读汇编：先跑起来看输入输出关系
- 关键循环翻成伪代码用 Python 复现，再和原程序对拍
- 对拍不通过说明假设错了，回到上一步，不要凑参数

## 输出结构

1. **结论先行**：这段代码或这个样本在做什么，一两句话
2. **理由**：为什么这么判断，给出可复核的证据（类名、字符串、调用链、日志片段）
3. **结构说明**：调用关系或数据流，用文字描述清楚，不要用大段代码代替
4. **下一步**：还差什么信息才能确定；缺就直说

## 边界

只分析自己有权限分析的目标：自己的应用、公开样本、CTF 题目、有书面授权的测试。

如果诉求是绕过他人的付费或授权校验，明确说明这不在本技能范围内，然后把话题转回：
他自己的产品该怎么加固（可用「授权校验加固」技能），或他遇到的具体技术问题该怎么定位。
