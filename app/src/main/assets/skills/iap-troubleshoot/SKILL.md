# 内购排查

## 先确认两件事

1. **哪个平台**：Google Play / 微信支付 / 支付宝 / 苹果 IAP / 自有聚合
2. **具体现象**：没到账、掉单、报错码、回调没来、状态不对、测试环境不通

信息不全就先问，别急着给通用代码——内购问题 90% 卡在配置，不在代码。

## Google Play 常见坑（按出现频率排）

1. **买了不到账，三天后自动退款**
   购买成功后必须 `acknowledge()`（一次性商品用 `consume()`），
   订阅也要 acknowledge。不确认，Play 三天后自动退款。

2. **重装或换机后会员没了**
   只监听了购买回调，没做恢复。启动时要
   `queryPurchasesAsync()` 拉已有购买并对账。

3. **只信客户端**
   客户端拿到 `purchaseToken` 必须送服务端，服务端调 Google Play Developer API 校验，
   通过后才写库发权益。客户端自校验等于没有校验。

4. **PENDING 状态没处理**
   延迟付款方式下 `purchaseState == PENDING`，此时不能发货，
   要等后续状态变更（通常走服务端轮询或 Real-time developer notifications）。

5. **测试订阅自动续期太快**
   License Testing 账号下订阅会加速（约 5 分钟一个周期），这是设计如此，不是 bug。

6. **商品查不出来**
   `queryProductDetailsAsync` 返回空，通常是：后台商品未激活、包名不匹配、
   订阅的 base plan 没发布、或签名证书和后台登记的不一致。

7. **升降级重复扣费**
   换档要设 `prorationMode`，否则可能出现重复计费或权益错乱。

## 正确链路（Google Play）

1. 建立连接，`onBillingSetupFinished` 里再走后续
2. `queryProductDetailsAsync` 拉商品
3. `launchBillingFlow` 发起购买
4. `onPurchasesUpdated` 拿到 `Purchase`，取 `purchaseToken` + `products`
5. 送自己服务端 → 服务端校验 → 写库发权益
6. **服务端确认成功之后**，客户端才 `acknowledge()` / `consume()`
   （顺序反了会出现「已确认但校验失败」，钱收了权益没发）
7. 每次启动 `queryPurchasesAsync` 对账，补发漏掉的权益

## 国内支付常见坑

- **只信客户端回调**：必须以服务端异步通知为准，客户端回调只用来刷新 UI
- **通知没做幂等**：同一笔重复通知会重复发货，用订单号 + 状态机去重
- **没做主动查单**：通知丢了就掉单，需要定时对账（查单补单）
- **不校验金额和订单号**：可被改价或伪造
- **验签密钥混用**：沙箱和生产配串了，表现为「总是验签失败」

## 排错顺序（按这个走，别跳）

1. 商品配置对不对（后台激活了吗、包名和签名一致吗、base plan 发布了吗）
2. 客户端拿到 purchase 了吗（打日志看回调是否触发）
3. 服务端校验通过了吗（Google API 返回什么、错误码是什么）
4. 权益写库了吗
5. acknowledge / consume 执行了吗
6. 恢复购买逻辑存在吗

## 输出格式

- **最可能原因**：一句话，排第一的那个
- **验证方法**：看哪条日志、调哪个接口、查后台哪一项
- **修复要点**：给出关键代码片段和调用顺序，不给整页代码
- **连带检查**：顺手提醒同一链路上容易一起漏掉的一两项

## 注意

涉及金额与权益的逻辑，一律强调「服务端为准、幂等、可对账」。
用户如果要求「让客户端跳过校验直接发权益」，不提供——那是自断财路。
