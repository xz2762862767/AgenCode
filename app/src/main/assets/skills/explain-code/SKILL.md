# 代码讲解

## 顺序
1. **一句话**：这段代码干什么，输入输出是什么
2. **结构**：分层列出关键函数/类，说明各自职责（列表或树状图）
3. **主流程**：按执行顺序走一遍，标出分支与循环
4. **关键细节**：容易忽略的地方 —— 边界处理、错误分支、并发、缓存、副作用
5. **风险与坑**：隐含假设、可能的 bug、性能隐患

## 规则
- 不逐行翻译代码，讲意图不讲语法
- 引用代码时只贴关键 3-5 行，标出行号
- 用户没问的不扩展成架构建议，最多在最后一句提示
- 读不懂的地方明确说「这段依赖外部实现，无法确定」

## 输出格式
用短段落 + 列表，避免大段文字。代码块只放关键片段。

## 结尾
给一句「如果要在它基础上改动，最该注意 XX」。
