# 文本整理

## 第一步：先判断是哪一种，别写成大杂烩
- 贴了一段长文，要「总结 / 提炼 / 讲了什么」→ **A 摘要**
- 给的是会议记录、语音转写稿，要「纪要」→ **B 会议纪要**
- 给的是一周做的事的流水账，要「周报」→ **C 周报**
- 判断不出来，就问一句「你要摘要、纪要还是周报」，不要三种都写。

## 通用规则（三种都适用）
- 只做整理，不加原文没有的信息，不评价好坏（除非用户要求）
- 口头语、重复、跑题内容全部剔除
- 数字、时间、结论性判断优先保留，举例与修辞优先删
- 原文有矛盾或数据打架时，单独列「需要注意」
- 缺失的信息写「未提及」，不要推测填空

---

## A. 摘要
输出三层：
1. **一句话结论**：不超过 40 字，说清讲了什么、什么立场
2. **要点**：3-6 条，每条一行，只留论证与数据
3. **可执行项**：原文里的建议、待办、风险提示（没有就写「无」）

长文超 8000 字时，先给目录式概要，再展开要点。需要引用原文时标出段落，不要整段复制。

## B. 会议纪要
1. **会议信息**：主题、时间、参与人（缺失写「未提及」）
2. **已达成决议**：每条只写「决定了什么」，不写讨论过程
3. **待办清单**：表格 —— 事项 / 责任人 / 截止时间 / 状态
4. **遗留问题**：没结论的话题，写清分歧点与下一步
5. **下次会议**：时间与议题（有则写）

规则：责任人只写明确提到的，不推测；时间含糊的（「下周」「尽快」）原样保留并标 `[待确认]`；同一人前后说法不一致时两条都留，标 `[有分歧]`。
需要用户确认的地方集中列在最后，最多 5 条。

```
## 待办
| 事项 | 责任人 | 截止 | 状态 |
|---|---|---|---|
| ... | ... | ... | 待开始 |
```

## C. 周报
核心：流水账写「做了什么」，周报写「做成了什么、影响了谁、下一步」。

1. **本周产出**：3-5 条，每条「动作 + 结果 + 量化影响」
   例：完成订单接口重构，P99 从 800ms 降到 210ms
2. **进行中**：进度百分比 + 预计完成时间
3. **问题与风险**：需要谁支持、做什么，写具体
4. **下周计划**：3 条以内，可验证

改写规则：「参与了 / 协助了」换成具体贡献；没有量化数据就用可观察结果替代（已上线、评审通过、缺陷清零）；没上线的不写「已完成」，写「已开发完成，待测试」；每条不超过两行。

直接给可粘贴的正文，末尾附一行「建议补充的数据：…」。
